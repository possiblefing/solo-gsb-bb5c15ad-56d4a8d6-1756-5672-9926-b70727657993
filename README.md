# 分支剧情一致性审校（Branching Story Checker）

为带布尔变量的分支剧情做**静态一致性审校**的 Web 应用：输入场景、前置条件、选项条件、状态赋值与跳转，
自动传播状态空间，标出 **不可达场景**、**条件永不成立的选项（死选项）**、**被目标前置条件阻断的跳转**，
点击任一问题即可查看**最近的可达路径**与**未满足条件**，并支持剧情 JSON 导入/导出。

技术栈：Node.js + Express + 原生 HTML/CSS/JavaScript（前端无构建、无框架）。

---

## 一条命令启动

需要已安装 Docker 与 Docker Compose（v2）：

```bash
docker compose up -d --build
```

启动完成后访问：

> **http://localhost:3000**

首次启动会自动完成两件事：

1. 容器镜像构建时安装全部 npm 依赖（仅 `express`）；
2. 应用首次运行时在数据目录初始化 `stories.json`，内置 **2 个示例剧情**：
   - 《迷雾古堡》——刻意覆盖全部问题类型（循环、不可达、死选项、阻断跳转）；
   - 《双结局小村》——无任何问题的对照示例。

停止 / 查看日志：

```bash
docker compose logs -f
docker compose down            # 停止（保留数据卷中的剧情）
docker compose down -v         # 停止并删除剧情数据
```

### 不使用 Docker（本地 Node.js ≥ 18）

```bash
npm install
npm start                 # 首次启动同样会自动写入示例数据到 ./data
# 或 npm test 运行冒烟测试
```

## 必要配置

所有配置均有默认值，**开箱即用**；如需调整通过环境变量传入：

| 变量 | 默认值 | 说明 | Compose 覆盖方式 |
| --- | --- | --- | --- |
| `HOST_PORT` | `3000` | 宿主机映射端口（容器内固定监听 3000） | `HOST_PORT=8080 docker compose up -d` |
| `PORT` | `3000` | 应用监听端口（容器内一般无需改） | 编辑 compose 的 `environment` |
| `DATA_DIR` | `/app/data`（容器）/ `./data`（本地） | 剧情 JSON 存储目录 | 编辑 compose 的 volume 映射 |

数据持久化：Compose 使用命名卷 `story-data` 挂载到 `/app/data`，重建/升级容器不会丢失剧情。

## 使用指南

### 编辑剧情

- **变量**：布尔变量名须匹配 `[A-Za-z_][A-Za-z0-9_]*`，可设定初始值。
- **场景**：每个场景有 `id`、标题、正文，以及**进入前置条件**（留空 = 无条件）。
- **选项**：包含
  - **显示条件**：选项在什么状态下出现/可点；
  - **状态赋值**：选择后把变量置为 `true/false`；
  - **跳转目标**：另一个场景；留空表示结局。
- 顶部下拉指定**起始场景**。`Ctrl/Cmd + S` 可快速保存并分析。

### 布尔表达式语法

```
变量名          如 has_key
true / false    布尔常量
! expr          非
expr && expr    与（也可用 AND）
expr || expr    或（也可用 OR）
( expr )        括号，可改变优先级
（空）          视为 true
```

### 审校结果

保存后右侧自动分析，问题分两级：

| 类型 | 级别 | 含义 |
| --- | --- | --- |
| **不可达场景** unreachable | 错误 | 从起点的任何可达状态都无法进入该场景 |
| **阻断跳转** blocked-transition | 错误 | 选项在某可达状态下条件成立、可被点击，但赋值后目标场景前置条件不成立 |
| **死选项** dead-option | 警告 | 选项条件在所属场景的**全部**可达状态下恒为 false，玩家永远选不到 |
| 起点受阻 | 错误 | 起点场景前置条件在初始变量状态下就不成立 |
| 语法错误 / 坏跳转 / 结构错误 | 错误 | 表达式无法解析、跳转目标不存在、id 重复/非法等 |
| 未声明变量 / 选项无目标 | 警告 | 表达式引用了未声明变量（按 false 求值）等 |

**点击问题**展开溯源详情：

- **① 最近的可达路径**：沿场景图反向搜索距目标最近的可达祖先，展示从起点到锚点的
  真实可达状态路径（实线），以及锚点之后走不通的场景链（红色虚节点）；点击任意节点可滚动定位到编辑器对应场景。
- **② 未满足条件**：在具体的变量快照上解释表达式为何为假（精确到每个失配变量，如 `has_key = false（要求为 true）`）。
- **死选项**额外给出**可满足性判定**：枚举条件引用变量的所有取值（>18 个变量时跳过），
  判断条件是否自相矛盾；若可满足，则给出相对示例状态**最少需要翻转的变量**，帮助定位“缺了哪段赋值剧情”。

右下方的 **场景可达图** 自动分层布局：绿色场景可达、红色不可达；
实线为可达跳转、黄色虚线为被前置条件阻断的跳转、暗红虚线为不可达分量内的跳转。

### 导入 / 导出

- **导出 JSON**：下载当前编辑内容（`branching-story/v1` 格式），同时服务端提供
  `GET /api/stories/:id/export` 带文件名下载。
- **导入 JSON**：选择导出的文件即可另存为一条新剧情（自动分配新的服务端 id，场景 id 保持不变）。

剧情 JSON 形态：

```json
{
  "format": "branching-story/v1",
  "name": "双结局小村",
  "startScene": "village",
  "variables": [{ "name": "helped_smith", "initial": false }],
  "scenes": [
    {
      "id": "village",
      "title": "村口",
      "text": "……",
      "precondition": "",
      "options": [
        {
          "label": "帮铁匠捞起锤子",
          "condition": "!helped_smith",
          "assignments": [{ "variable": "helped_smith", "value": true }],
          "target": "forest"
        }
      ]
    }
  ]
}
```

## 为什么含循环的剧情分析也能终止

分析器把剧情展开为**有限状态空间上的可达性传播**：

- 每个状态节点是 `(场景 id, 全量布尔变量快照)`；
- 在某场景的某状态下，依次检查每个选项的条件，成立则应用赋值并把
  `(目标场景, 新状态)` 入队；
- 用集合对节点 key 去重，**同一节点永不重复扩展**。

设场景数为 S、变量数为 V，不同节点总数至多为 **S × 2^V**（报告头部会展示这个上界与实际产生的节点数）。
状态数有上界、每个节点至多扩展一次，所以即使剧情存在自循环或回头路（如“大门 ↔ 庭院”来回走），
传播也必然终止——循环不会再产生新状态时自然收敛。

### HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/stories` | 剧情列表 |
| POST | `/api/stories` | 新建（body 为剧情 JSON） |
| GET/PUT/DELETE | `/api/stories/:id` | 读取 / 更新 / 删除 |
| GET | `/api/stories/:id/analysis` | 分析已保存剧情 |
| POST | `/api/analyze` | 直接分析 body 中的剧情（无需保存） |
| GET | `/api/stories/:id/export` | 导出 JSON 文件 |
| POST | `/api/import` | 导入 JSON（自动新建） |

## 已知边界

- 可满足性枚举仅针对选项条件引用的变量，且变量数 ≤ 18 时执行（防止 2^V 爆炸）；超过时跳过该建议，
  不影响可达性分析本身（可达性按实际状态惰性扩展，不做全枚举）。
- 存储为单机 JSON 文件，面向个人/小团队审校场景，不含鉴权与并发写控制。
